Sessions

Continue a real provider conversation after a follow-up, reload, restart, or supported context compaction.

How sessions work

A session connects the visible transcript, active project, and provider-specific continuation state. Sparky saves the records required to reopen that conversation rather than treating every message as an unrelated request.

Resuming a session

Sessions are in the sidebar of the desktop app. Click any one to reload its transcript and continue from the same saved provider conversation.

What is preserved

  • The visible user and assistant transcript.
  • The provider session binding required for a true follow-up turn.
  • Opaque continuation state used by providers such as GPT-5.6.
  • Project and session records stored under Sparky's session directories.

Sessions are not Memory

A session preserves one line of work. Memory stores selected durable information that should be reusable in another session. Keep temporary tool output, errors, and implementation details in the conversation. Save stable preferences or project conventions in Memory.

Long conversations and compaction

Sparky 1.1.2 no longer applies the old fixed 40-round cutoff to longer coding tasks. Codex OAuth conversations can use /compact, and a context-overflow recovery compacts the same provider thread before retrying once.

If required resume state is missing, Sparky reports that problem instead of quietly substituting a fresh hidden conversation. Read the complete 1.1.2 continuity reference for the full behavior.

When a turn is complete

An incomplete provider stream is not treated as a successful turn. Sparky waits for a valid user-facing summary, records the terminal state, and rejects late completion events after a turn has been stopped.

Stop and resume safely

Stop settles the active UI state immediately while provider cancellation continues in parallel. Late response text and late completion events are rejected after interruption. A warm provider session with no active turn remains ready, so stopping one operation does not mean the entire session was discarded.

Before continuing, read the terminal state in the timeline. A stopped turn, provider failure, environment error, and completed turn mean different things and can require different recovery.

Desktop notifications

Sparky can issue one native notification when an agent turn settles on Windows, macOS, or Linux. The notification contains the first seven response lines so you can recognize the result while working elsewhere. Return to the session for the complete summary, tool evidence, and diff.
