Read & Edit Files

Inspect project files, apply targeted text changes, and review the resulting diff and file statistics in the same task timeline.

How it works

When you ask Sparky to modify a file, it reads the current content, prepares a targeted change, applies it through the file tool, and exposes the result in the timeline and Diff surface. Review the working tree before committing or publishing.

Reading files

Sparky reads any text file in your project. It can read entire files or specific line ranges. For large files, it reads only the relevant sections to stay efficient.

Example prompt
"Show me the contents of src/main.ts"
"What's in the config file?"
"Read lines 50-100 of app.py"

Editing files

When you ask for a change, Sparky uses the edit tool to make precise, targeted replacements. It finds the exact text to change and replaces it — no need to rewrite the whole file.

Example prompt
"Change the port in config.ts from 3000 to 8080"
"Rename the function 'getData' to 'fetchData' in all files"
"Add error handling to the login function in auth.ts"

Creating files

When a file doesn't exist yet, Sparky creates it. It automatically creates any missing parent directories.

Example prompt
"Create a new React component called UserCard in src/components"
"Write a README.md for this project"

Viewing changes

Sparky shows you a diff — a side-by-side comparison of what changed. Added lines appear in green, removed lines in red. You can review every change before it's committed.

Stale files, sequential edits, and CRLF

Version 1.1.2 strengthens editing on Windows and in CRLF-formatted files. Sequential edits use current snapshots, and stale-file detection rejects an edit when the working copy no longer matches the content it was prepared against. Ambiguous replacements fail instead of changing an arbitrary match.

If an edit fails, read the tool error. Reopen the latest file content, narrow the requested replacement, and retry. This is safer than forcing a broad replacement over a file that may have changed in another editor.

Tool states and file statistics

The timeline distinguishes Running, Completed, Failed, Stopped, and Declined. File-change statistics can update while work is still active, but the final status and diff are the evidence to review before treating the edit as complete.

Limitations

  • Only works with text files — images, binaries, and other non-text files can't be edited.
  • Generated files, minified bundles, and very large text payloads may be poor direct-edit targets; prefer their source files and normal build process.
  • A visible diff is review evidence, not an automatic guarantee that the change is correct or that unrelated work was preserved.
