CHATS & MEMORY

Memory

Give Sparky durable context you explicitly approve, without repeating the same preferences and conventions.

Introduced in Sparky 1.1.7

Sparky 1.1.7 is the first published update with Memory. It is stored locally and designed for user-approved facts, preferences, conventions, and decisions that help future sessions.

What to save

  • Your preferred coding style or review conventions.
  • Stable project decisions and architecture notes.
  • Workflow preferences that should carry across sessions.
  • Useful project context that you explicitly want Sparky to remember.

Never save API keys, passwords, tokens, private keys, or other credentials. Memory is for durable context, not secrets.

Global and project Memory

Global memories apply across projects, such as your preferred handle or general coding conventions. Project memories stay with one workspace, such as an architecture decision or local test command.

Stateless chats use a separate project-free Memory store, so workspace context stays isolated until you open a project.

Manage Memory

Use Sparky's Memory tools or Settings to manage entries:

  1. Search when a remembered fact may be relevant.
  2. Add a fact only after you approve what should be saved.
  3. Update an entry after confirming the change.
  4. Delete an entry when you ask Sparky to forget it.

Sparky can use relevant approved memories as context, but memories do not override your current request.
