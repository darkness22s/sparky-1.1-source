What is Sparky?

Sparky is a desktop AI coding workspace. It combines a project-aware conversation, file and diff views, a terminal, web search, browser preview, model controls, and persistent Memory in one application.

The workspace and its coordination server run locally. Provider requests are sent to the provider you configure, while project tools operate against the folder you opened. Review the provider's own data policy before sending sensitive code or attachments.

How it works

  1. Open a project. Sparky inventories relevant workspace context and keeps tools scoped to that project.
  2. Choose Plan or Build. Plan investigates without editing; Build can change files and run tools.
  3. Describe the outcome. Include constraints, relevant files, and the evidence that should prove the work.
  4. Follow the timeline. Tool states show what is running, completed, failed, stopped, or declined.
  5. Review the result. Inspect changed files, diffs, terminal output, and the final summary.

Plan, Build, sessions, and Memory

Plan mode investigates with a read-only tool policy. Build mode enables normal implementation tools. A session preserves the current conversation and provider continuation state. Memory stores selected reusable facts beyond one session.

These systems complement one another: plan the approach, build the change, continue the same provider conversation when you follow up, and save only durable preferences or project rules to Memory.

Workspace surfaces

Open supporting tools beside the active thread. Each surface keeps the current project and task in view:

BrowserOpen a local app or URL and inspect the result.
TerminalRun tests, builds, package commands, and one-off scripts.
FilesBrowse the project tree and read the exact files involved.
DiffReview working-tree or thread changes before you commit.

The conversation timeline stays connected to these surfaces, so a command, file change, web search, or browser action can be reviewed in the context of the task that requested it.
