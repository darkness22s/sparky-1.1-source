Writing Prompts

Give Sparky a clear outcome, the boundaries that matter, and the evidence you expect before the task is complete.

How to think about prompts

Talk to Sparky like a developer joining the task with access to the active project. Name the result you want, point to known context, state what must not change, and describe how to verify the work.

Reusable task shape
“In [scope], produce [outcome]. Preserve [constraints]. Verify it with [tests or inspection], then summarize [evidence].”

Choose Plan or Build

Plan mode uses Sparky's Rust-native read-only planning flow. Use it to inspect unfamiliar code, compare approaches, ask decision questions, and produce a structured plan without editing files. Build mode restores implementation tools for edits, commands, searches, previews, and verification.

State the same task in either mode. The mode changes the allowed actions, not the meaning of your request.

Good prompts

  • "The search page crashes on empty query — find handler in SearchPage.tsx and add a check"
  • "Find all calls to old pricing API and update them"
  • "Explain auth flow from login to session creation"
  • "Run tests, show failures, fix them"

Prompts that don't work well

  • "Fix it" — fix what? Which file?
  • "Make it better" — better how?
  • "Write a website" — too broad

Follow-up prompts

Continue in the same session when the next message depends on earlier work. Sparky reloads the visible transcript and the provider continuation state required for a true follow-up:

  • "That is close, but move the validation earlier"
  • "Also update the error message"
  • "Now do the same for other endpoints"

Use images as task context

Attach a screenshot, mockup, diagram, or other supported image when visual evidence matters. Sparky validates the attachment and forwards it as a multimodal request part to a provider that supports images. An image-only message receives an effective prompt, but a short instruction such as “Match this empty-state spacing in the current component” produces a clearer task.

Provider capability matters: An attachment can travel through Sparky correctly while the selected model still lacks image support. If the provider rejects it, switch to a multimodal model or describe the relevant detail in text.

Use Memory for durable context

Do not repeat stable preferences and project conventions in every prompt. Save them as a global or project memory, then keep the prompt focused on the current outcome. Temporary errors, one-off file positions, and guesses should remain in the session instead of becoming persistent memories.
