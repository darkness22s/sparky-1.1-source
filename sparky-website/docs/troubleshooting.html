Troubleshooting

Identify whether the blocker belongs to installation, provider access, model capability, project tools, Memory, or the active session, then use the matching recovery.

API key not set

Open Settings, Models, select the intended provider, and add that provider's credential or supported account connection. A key for one provider does not authenticate another. If the key is present but rejected, confirm that it is active, has access to the selected model, and is not surrounded by copied whitespace.

The app is blocked during installation

Use only a package downloaded from the official Sparky download page. The current Windows build is unsigned, so SmartScreen can require More info and Run anyway. macOS can require a Finder or Privacy & Security confirmation for an app that is not notarized. Choose the macOS package that matches Apple Silicon or Intel.

Sparky seems slow or hangs

Check the timeline to see whether Sparky is waiting for the provider, running a terminal command, using a tool, or reporting an environment error. Use Stop to settle the active turn in the UI. If the provider is repeatedly slow or unavailable, try another model or provider; if a command is still running, inspect its terminal output before deciding whether to stop it.

Sparky made the wrong edit

Open the Diff surface and identify the incorrect hunk. Ask for a precise correction and name what must be preserved. If you need a Git restoration, state the exact files and confirm that unrelated working-tree changes must remain untouched. Do not assume a broad “undo” is safe in a dirty project.

Command timed out

Read the captured output first; a timeout does not prove the command made no progress. Split long checks into focused commands, increase the timeout when the command has a legitimate finite duration, or keep a development server or watcher in a dedicated terminal where it can remain active.

Sparky stopped before finishing

Sparky 1.1.2 no longer uses the old fixed 40-round cutoff. If a task stops, read the final status first: it should distinguish a completed task, a user cancellation, a provider error, or an environment failure. After resolving any reported problem, continue in the same session so Sparky can reuse the preserved conversation and provider state. For longer work, see Long conversations and compaction.

A follow-up lost conversation context

Confirm that you reopened the same session instead of starting a new thread. Version 1.1.2 persists provider bindings and should fail visibly when required resume state is missing instead of silently creating a hidden replacement conversation. Preserve the error text, selected provider, model, and session when reporting the problem.

A reasoning level or model is missing

Sparky does not fabricate unsupported controls. Model names, context windows, and reasoning-effort choices come from provider metadata and can change independently of the app. Refresh the relevant provider configuration, confirm the credential has catalog access, and reopen the model picker. Disabled OpenCode variants are intentionally filtered.

An image prompt fails

Confirm that the file is a valid supported image and that the selected provider model accepts multimodal input. Sparky validates attachments and forwards image data with its MIME type, but it cannot add image capability to a text-only model. Add a short text instruction so the visual task is unambiguous.

Memory did not save or is not reused

Check whether the entry is global or project-scoped, search for an existing entry with the same subject, and retry after the visible loading or save error. Correct conflicting or stale entries. Memory errors are contained and should not crash the active coding session, so include the needed context in your current prompt while recovering.

Browser preview does not connect

Verify that the local development server is running and note its exact URL and port. Reopen the preview, then retry the requested browser action. If a popup or click was interrupted, start a fresh action after the preview status returns to ready.
